# PRD（最终冻结版）

**产品名称：CodeAtlas（代码图谱）**

---

## 1. 产品基本信息

### 1.1 产品名称

- **英文名**：CodeAtlas
- **中文名**：代码图谱
- **全称来源**：Code Atlas（AI Coding Atlas 的品牌缩写）

### 1.2 Slogan

> 选对 AI 编程工具，用对工作流

### 1.3 副标题（解释性 & SEO）

> AI 编程工具对比、教程与使用/购买指南

---

## 2. 产品愿景与定位

### 2.1 产品愿景

让开发者在 AI 编程工具爆炸增长的环境中，**少踩坑、少折腾、少浪费钱**。

### 2.2 一句话定位

CodeAtlas 是一张从「选工具 → 用能力 → 跑工作流 → 合理购买」的 AI 编程地图。

### 2.3 产品边界（明确不做）

- ❌ 不做 AI 编程百科
- ❌ 不做协议 / MCP / Skills 文档镜像
- ❌ 不做提示词大全
- ❌ 不提供账号共享、代充、绕价方案

---

## 3. 竞品分析与差异化定位

### 3.1 竞品分析

| 竞品 | 定位 | 优势 | 劣势 |
|------|------|------|------|
| **There's An AI For That** | AI工具大全，覆盖所有AI领域 | 工具数量多（10000+），SEO强 | 不聚焦编程，无深度对比，无购买指导 |
| **AI Tool Report** | AI工具新闻+推荐 | 更新快，有Newsletter | 偏新闻向，缺乏结构化对比和教程 |
| **Futurepedia** | AI工具目录 | 分类清晰，有评分系统 | 泛AI领域，编程工具深度不足 |
| **Product Hunt** | 新产品发现平台 | 社区活跃，第一手信息 | 非垂直领域，无系统性对比 |
| **官方文档** | 各工具官方文档 | 权威、准确 | 各自为政，无横向对比，无购买建议 |
| **技术博客/YouTube** | 个人评测内容 | 有实操体验 | 碎片化，时效性差，主观性强 |

### 3.2 竞品核心问题

1. **广而不深**：大多数AI工具导航站追求覆盖面，对AI编程工具缺乏深度分析
2. **缺乏决策支持**：只罗列工具，不给结论，用户仍需自行判断
3. **忽视购买环节**：几乎没有竞品关注"怎么买"这个关键问题
4. **内容碎片化**：教程散落在各处，缺乏系统性的工作流指导
5. **中文内容缺失**：优质的AI编程工具对比内容几乎都是英文

### 3.3 差异化定位

CodeAtlas 的核心差异化：

| 维度 | 竞品做法 | CodeAtlas 做法 |
|------|----------|----------------|
| **领域聚焦** | 泛AI工具 | 只做AI编程工具 |
| **内容深度** | 工具卡片+简介 | 深度对比+场景分析+能力矩阵 |
| **决策支持** | 罗列信息 | 结论先行，明确推荐 |
| **购买指导** | 无或仅放链接 | 完整购买路径+合规说明+成本分析 |
| **实操导向** | 功能介绍 | SOP教程+可复制模板 |
| **语言市场** | 英文为主 | 中文优先，服务中文开发者 |

### 3.4 竞争壁垒

**短期壁垒（6个月内建立）**

- 中文AI编程工具领域的内容先发优势
- 结构化的对比数据和决策框架
- 高质量SOP教程积累

**中期壁垒（6-12个月）**

- 用户信任和品牌认知
- SEO长尾词占位
- 社区和用户反馈闭环

**长期壁垒（12个月+）**

- 工具厂商合作关系
- 企业客户资源
- 数据资产（使用数据、对比数据、价格历史）

### 3.5 市场机会

- **时机窗口**：AI编程工具正处于爆发期，用户选择困难症明显
- **中文市场空白**：目前无专业的中文AI编程工具对比平台
- **付费意愿**：开发者群体付费能力强，对效率工具投入意愿高
- **B端潜力**：企业技术选型需求旺盛，咨询服务有市场

- 1–10 人技术团队工程师
- 前端 / 后端工程师

## 5. 核心产品原则（不可违反）

1. **结论优先**：每个对比页必须有明确建议
2. **任务导向**：所有内容必须服务"完成一个任务"
3. **能力内化**：MCP / Skills / Prompt 不单独成体系
4. **页面克制**：一个页面解决一个问题
5. **合规底线**：所有购买信息可追溯、可解释

### 7.2 工具库（Tools）

**目标**

成为 AI 编程工具的事实页 + 决策页

#### AI 编程产品定义（收录标准）

CodeAtlas 的 `Tools` 列表**只收 AI 编程产品**，用于避免“模型/云平台/网关/观测”与“编程工具”混在一起导致选型误差。

**我们认为“AI 编程产品”必须满足：**

- **目标用户**：主要面向软件开发者/工程团队（而非泛业务人群）
- **核心产出**：直接产出或改动软件工程产物（代码、补丁/PR、测试、配置、脚本、评审意见等）
- **核心工作流**：围绕 SDLC（写代码、读代码、重构、调试、测试、代码评审、CI/CD、仓库协作）提供能力

**典型收录（示例）**

- IDE/编辑器/插件：Cursor、Windsurf、GitHub Copilot、JetBrains AI Assistant、Gemini Code Assist、通义灵码等
- CLI/Agent：Aider、Claude Code、OpenHands、SWE-agent、Cline 等
- PR/代码审查：CodeRabbit、Codium PR-Agent、GitLab Duo 等
- 代码检索/Repo Chat：Sourcegraph Cody、Greptile 等
- “从需求到代码”的生成型产品：v0、Bolt.new、Lovable（以工程产出为目标）

**明确不收录到 `Tools`（但可在“使用&购买/教程/模板”中讨论）**

- **大模型/推理/云平台与聚合入口**：例如 OpenAI API、Azure OpenAI、AWS Bedrock、阿里云百炼/通义 DashScope、火山方舟、OpenRouter、Together.ai、Replicate 等
- **网关/路由/可观测/成本治理**：例如 LiteLLM、Portkey、Langfuse、Helicone 等
- **泛用对话产品**：例如 ChatGPT、Claude、Gemini（除非以“编程产品形态”独立提供：如 Claude Code、Gemini Code Assist 等）

**分类方式（按任务）**

- 代码补全 / 生成
- Agent 编程
- 测试与质量
- 代码审查 / PR Review
- Repo Chat / 搜索
- 文档生成
- DevOps / CI

#### 工具详情页（Tool Page）

**核心字段（冻结）**

| 字段类型 | 具体内容 |
|----------|----------|
| 基础信息 | 工具定位（适合谁 / 不适合谁）、核心能力标签 |
| 能力支持 | Repo 级上下文、Agent 执行、MCP Server、Skills / Plugins、本地命令、外部系统（GitHub / DB / Jira 等）、权限等级（只读 / 读写 / 执行） |
| 使用信息 | 典型使用场景、优点 / 局限、上手成本（时间 + 依赖） |
| 商业信息 | 价格概览（含更新时间）、隐私与数据策略 |
| 关联内容 | 替代工具、关联教程、关联对比 |

#### 工具页 CTA（关键）

**固定「用 / 买」区块**

- ✅ 开始使用 → 跳转入门教程
- 💳 查看购买 → 展开购买卡片

**购买卡片字段（全站唯一数据源）**

- 价格模式概览
- 官方 / 授权购买入口
- 是否支持教育 / 团队 / 企业
- 是否支持发票 / 合同
- 更新时间
- 推广声明

### 7.4 教程（Tutorials）

**目标**

不是讲概念，而是带你跑完一次

**教程类型（内部）**

- 入门 SOP：第一次用某工具/组合，目标是“跑通一次”
- 场景实战（任务 SOP）：围绕具体任务的可复制流程（写功能/改 Bug/补测试/选型等）
- 自动化 / Agent：把多步闭环固化成自动化（命令/脚本/MCP/CI），强调权限边界与回滚
- 团队实践：团队落地（账号/Key、权限、审计、试点→推广）
- 质量与风险控制：成本/合规/安全/验收与最小验证的“护栏”

**教程页模板（SOP · 最终版）**

| 序号 | 模块 | 说明 |
|------|------|------|
| 1 | 🎯 目标 | 本教程要达成什么 |
| 2 | 🧩 适用工具 & 能力 | 需要哪些工具 |
| 3 | 🛠 SOP 步骤 | 具体操作流程 |
| 4 | 🧠 关键 Prompt / 交互技巧 | 1–3 条核心技巧 |
| 5 | ⚠️ 常见失败 & 修复 | 踩坑指南 |
| 6 | ✅ 验收标准 | 如何判断成功 |

> ⚠️ 不允许出现纯 Prompt 教程

### 7.6 使用 & 购买（Use & Buy）

**定位**

聚合引导页，不是内容库

#### 7.6.1 如何使用（Use）

**页面目标**：新用户 5 分钟知道从哪开始

**页面结构（固定）**

1. 新手起步
2. 按任务使用
3. 能力使用判断（何时用 Agent / MCP）
4. 常见坑与修复
5. 使用原则（人永远在环）

> 📌 全部链接到现有教程，不重复正文

#### 7.6.2 如何购买（Buy）

**页面目标**：买得清楚、不踩坑

**页面结构**

1. 购买前思考
2. 定价模式说明
3. 推荐购买路径（个人 / 团队 / 企业）
4. 渠道类型与合规说明
5. 成本与风险提示
6. 决策指路（工具 / 对比 / 教程）
