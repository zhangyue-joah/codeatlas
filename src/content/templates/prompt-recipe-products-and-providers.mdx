template: |
  # 接入确认清单（复制后把括号内容替换掉）
  我准备接入的路径类型是（官方 API / 授权聚合或路由 / 自建网关）。
  我准备使用的提供方/服务是（…）。
  使用场景：（个人开发/团队/企业），地区/合规要求（…），预算（…），是否允许代码外发（是/否）。

  请按下面格式输出结论（必须引用官方/权威链接，缺失就标注“不确定”）：
  1) 合规与可追溯：是否需要实名/合同/发票？key 是否绑定到我自己的官方账号？是否可审计？
  2) 接入方式：是否支持 OpenAI-Compatible（baseUrl + /v1）？不支持的话用什么 SDK/适配？
  3) 计费与限流：计费口径、速率限制、并发、失败重试、是否有用量仪表盘。
  4) 数据与隐私：日志/提示词/输出是否会被存储？保留多久？是否可关闭/脱敏？
  5) 风险提示：哪些做法不建议（共享账号/代充/绕价/不可追溯 key/灰色中转）。
  6) 最小验证：给一个最小请求示例（list models 或一次 chat），并说明成功标准。

  ---
  # 一句话提示词模板（通用，适配 IDE/插件/CLI/Agent）
  目标：（一句话）
  验收标准：（1-3 条可验证标准）
  约束：（只改哪些文件/不做什么/必须跑哪个验证命令）
  风险：（权限、数据、依赖、迁移）

  请你先输出计划（文件列表 + 为什么 + 风险点 + 验证命令），我确认后再开始改代码。
notes:
  - 本模板只整理“官方/授权/自建合规网关”的路径；任何共享账号、代充、绕价、不可追溯 key 的中转都不收录/不建议。
  - 产品迭代很快：先用“任务类型 + 权限/合规边界”筛选，再看体验与价格。
  - 需要“提示词/工作模式固化”时，优先用各工具的 repo 规则/Chat Modes/模板系统，而不是每次手写一遍。

## 3) 不收录 / 不建议（合规底线）

- 共享账号、代充、绕价、可疑低价“包月”、不可追溯 key。
- 声称“随便填 baseUrl 就能用”的灰色中转（无主体、无条款、无审计、无稳定 SLA）。
- 要求你把官方 key 交给第三方保管，且无法提供明确的权限隔离/审计/撤销方式。
