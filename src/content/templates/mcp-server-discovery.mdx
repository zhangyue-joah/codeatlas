template: |
  # MCP Server Discovery & Setup Checklist
  ## 1) 先选 server（优先 Registry）
  - 在 MCP Registry 搜索：按“我需要的能力”而不是按热度。
  - 只选你信任的发布主体；能看源码就更好。

  ## 2) 先定权限边界（默认只读）
  - Filesystem：只授权单个项目目录（不要授权 ~ 或 /）。
  - GitHub：从只读 token 开始，必要时再逐步放开写权限。
  - 数据库：优先只读账号 + 限定 schema；先跑最小查询再扩大范围。

  ## 3) 最小可用配置（示例：GitHub + Filesystem）
  {
    "mcpServers": {
      "github": {
        "command": "npx",
        "args": ["-y", "@modelcontextprotocol/server-github"],
        "env": {
          "GITHUB_TOKEN": "YOUR_GITHUB_TOKEN"
        }
      },
      "filesystem": {
        "command": "npx",
        "args": ["-y", "@modelcontextprotocol/server-filesystem", "/ABSOLUTE/PATH/TO/PROJECT"]
      }
    }
  }

  ## 4) 上线前验收（必须可追溯）
  - 记录：谁配置的、配置文件位置、授权目录、token 范围、回滚方式
  - 最小验证：列出一次“只读”操作并记录结果（例如列目录/读文件/列 PR）
notes:
  - MCP 的价值是“把外部工具/数据接进对话”，风险也在于此：先从只读与单目录授权开始。
  - 建议把配置与密钥纳入团队治理：统一版本、统一审计、统一撤销/轮换机制。
