## Skill 目录结构

```
skill-name/
├── SKILL.md              # 必需：入口文件，含 YAML frontmatter
├── references/           # 可选：详细文档/证据/索引
│   └── index.md          # 推荐：导航索引
├── scripts/              # 可选：辅助脚本/自动化
└── assets/               # 可选：模板/配置/静态资源
```

最小版本只需要 `SKILL.md`（后续可添加 `references/`）。

## YAML Frontmatter 规则

```yaml
---
name: skill-name
description: "做什么 + 何时使用（触发条件）"
---
```

- `name` 必须匹配 `^[a-z][a-z0-9-]*$`，应与目录名一致
- `description` 必须可判定（不是"帮助处理 X"），包含具体触发关键词

## 创作规则（不可协商）

1. **快速参考用于短小、可直接使用的模式**
   - 保持 <= 20 个模式
   - 需要段落解释的内容放到 `references/`

2. **触发必须可判定**
   - frontmatter `description` 应说明"做什么 + 何时用"，带具体关键词
   - "何时使用"必须列出具体任务/输入/目标，不是模糊的帮助文本
   - "不适用场景 / 边界"是可靠性的必要条件

3. **不要在外部细节上虚张声势**
   - 如果材料没有证明，就说明并提供验证路径

## 工作流程（材料 → Skill）

不要跳过步骤：

1. **范围**：写 MUST/SHOULD/NEVER（三句话即可）
2. **提取模式**：选择 10-20 个高频模式（命令/代码片段/流程）
3. **添加示例**：>= 3 个端到端示例（输入 → 步骤 → 验收）
4. **定义边界**：超出范围的内容 + 必需输入
5. **拆分参考**：长文本移到 `references/` + 写 `references/index.md`
6. **应用质量门**：运行检查清单和验证器

## 质量门（交付前检查清单）

1. `name` 匹配 `^[a-z][a-z0-9-]*$` 且与目录名一致
2. `description` 说明"做什么 + 何时用"，带具体触发关键词
3. 有"何时使用此技能"，带可判定的触发条件
4. 有"不适用场景 / 边界"以减少误触发
5. 快速参考 <= 20 个模式，每个都可直接使用
6. 有 >= 3 个可复现的示例
7. 长内容在 `references/`，`references/index.md` 可导航
8. 不确定的声明包含验证路径（不虚张声势）
9. 读起来像操作手册，不是文档堆砌
