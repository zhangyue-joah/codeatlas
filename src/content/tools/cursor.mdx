## 适合用 Cursor 的一个判断

如果你的目标是“把一件事做完并产出可提交的改动”，而不是只要补全几行代码，那么 Cursor 的整体体验通常更贴近这个诉求。

## 官方怎么介绍自己（抓重点）

Cursor 官方在「Introduction」里把核心能力概括为 3 件事：

- **AI code completion**：基于代码上下文的 Tab 补全（行/函数/样板），并会逐步适配你的编码习惯。
- **Conversation interface**：统一 AI 交互界面（Ask/Edit/Agent）用于理解、修改代码并应用改动。
- **Intelligent tools**：面向复杂任务的工作流（多文件改动、重构、排障等）。

官方入口（从低成本到高收益）：

- `Tab`：智能补全
- `Cmd/Ctrl + K`：Inline Edit（就地改代码）
- `⌘I`：打开 Composer（Ask/Edit/Agent）

## Context：让它“懂你仓库”的关键

官方强调 Context 是所有 AI 功能的底座，核心点包括：

- 打开仓库后会进行 codebase indexing（让代码可被当作上下文使用）。
- 用 `@files` / `@folders` / `@web` / `@git` 精确控制提供的上下文。
- 用 Rules（rules for AI）把团队约束固化，降低扩范围与返工。
- 需要外部上下文/工具时可接 MCP（Model Context Protocol）。

## 使用建议（安全第一）

- 先用只读/建议模式跑通 SOP，再逐步开放写入与执行权限
- 所有 Agent 产出都要走代码审查与测试验证
- 如果接入 MCP：默认保留“执行前确认”，谨慎开启自动执行（如 Yolo mode）
