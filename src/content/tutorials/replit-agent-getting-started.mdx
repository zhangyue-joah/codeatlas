type: getting-started
difficulty: beginner
goal: 在 30-60 分钟内得到一个可运行原型，并明确下一步迭代清单。
requiredTools:
  - Replit（在线 IDE）
  - Replit Agent 或 Ghostwriter（按你的版本/地区）
requiredCapabilities:
  - read-write
estimatedTime: 30-60 分钟
stepsOverview:
  - 写清“用户故事 + 验收标准 + 不做什么”
  - 先生成最小可运行版本（MVP）
  - 用运行结果反向驱动修正
  - 把关键逻辑拆成小任务逐步迭代
  - 导出代码并做基本质量检查
steps:
  - step: 1
    title: 写“可运行”的验收标准
    description: 用可验证的方式描述完成标准（页面/接口/交互/错误处理）。
  - step: 2
    title: 先做 MVP
    description: 先让 Agent 生成最小可运行版本，不要一上来追求完整架构。
  - step: 3
    title: 运行并观察
    description: 把实际运行结果当证据，指出与验收标准不一致的地方。
  - step: 4
    title: 分解迭代清单
    description: 把需求拆成 5-10 个小任务，每次只改一个点。
  - step: 5
    title: 导出与质量兜底
    description: 把代码导出到本地仓库，补齐 lint/test/CI 等最小质量关卡。
keyTips:
  - 原型工具擅长“快”，不擅长“长期维护”；尽早把代码迁出并建立质量门槛
  - 先跑起来，再追求结构与优化
safety:
  checklist:
    - 不要把生产密钥/真实用户数据放进在线原型环境
    - 明确版权与依赖来源，避免直接复制不明授权代码
  updatedAt: "2025-12-28"
commonFailures:
  - problem: 一开始就追求“完整系统”导致越做越乱
    solution: 先 MVP，后迭代；每次只改一个点
  - problem: 代码可运行但难维护
    solution: 导出到本地仓库，补 lint/test/CI，并做一次结构性重构
acceptanceCriteria:
  - 原型可运行且满足最小验收标准
  - 你有明确的下一步迭代清单

## 适合 Replit 的任务

- 需要“快速验证想法”的 Demo/原型
- 允许自动生成较多样板代码，并愿意后续迁移到本地仓库治理质量
