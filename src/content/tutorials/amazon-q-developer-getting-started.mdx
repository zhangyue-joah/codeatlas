steps:
  - step: 1
    title: 确认账号与权限
    description: 先确认你能正常使用 Q，并了解组织/团队策略（权限、审计、数据）。
  - step: 2
    title: 写验收标准（可验证）
    description: 3 条以内，避免模糊需求导致生成偏离。
  - step: 3
    title: 先要计划
    description: 让 AI 列出要改的文件/符号与风险点，你确认后再写入。
  - step: 4
    title: 小步实现 + 最小验证
    description: 用 lint/test/build 任意一个命令作为证据。
    code: |
      npm run lint
  - step: 5
    title: 提交前复查与复盘
    description: 对照验收标准，检查变更范围与回滚路径。
keyTips:
  - 企业落地优先明确：权限、审计、数据留存策略
  - 让 AI 引用具体代码位置（文件/方法）而不是泛泛输出
safety:
  checklist:

## 小提醒

如果你的任务需要“多步闭环 + 自动跑命令”，可以考虑把 Q 用作“建议/解释层”，再叠加一个可控的 Agent 工具完成闭环。
