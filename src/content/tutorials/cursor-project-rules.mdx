## 为什么要写“项目规则”

Cursor 的 Agent 能力越强，越容易出现两类问题：

- **扩范围**：顺手重构、改风格、动无关文件
- **无证据**：改完就算，没有验证命令、没有回滚路径

“项目规则”的目标不是把 AI 管死，而是把它的输出**变得稳定、可审计、可回滚**。

## 直接复制一份模板（推荐）

- 先用这份模板起步：`/templates/cursor-project-rules`
- 不要一上来写 200 行规则：先用 10–20 行把“范围/验证/安全”三件事钉死

## 一套最小可用结构（建议固定成 4 段）

1. **Scope（范围）**：只改哪些、不改哪些；需要扩范围必须先申请
2. **Code Style（风格）**：遵循现有 lint/format/命名；不引入新风格体系
3. **Quality Gate（验证）**：必须给出并执行最小验证命令
4. **Safety（安全）**：不写密钥、不跑破坏性命令；一切可回滚

## 验证方法（跑一次就够）

挑一个**可回滚的小改动**（比如修一个边界 case、补一个最小测试），让 Agent 按下面顺序输出：

1. 计划（文件清单 + 风险 + 验证命令）
2. 变更摘要（每个文件做了什么、为什么）
3. 最小验证结果（如果无法执行，要明确说明）

只要它能稳定做到上面三点，这份规则就“活”了。下一步再慢慢加细节。
