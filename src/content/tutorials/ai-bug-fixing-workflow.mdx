## 为什么用 AI 改 Bug

AI 工具在 Bug 修复中的价值：

- **快速分析**：根据错误日志快速定位可能的原因
- **代码理解**：解释复杂代码逻辑，帮助理解问题
- **方案生成**：生成修复方案供参考
- **减少遗漏**：提醒可能忽略的边界情况

## 提示词模板

### 分析 Bug 原因

```
我遇到了一个 Bug：

错误信息：
[粘贴错误日志]

复现步骤：
1. [步骤1]
2. [步骤2]
3. [步骤3]

预期行为：[描述预期]
实际行为：[描述实际]

请分析可能的原因，并给出排查方向。
```

### 请求修复方案

```
我已经定位到问题在 [文件名] 的 [函数名]。

问题原因：[描述原因]

请给出修复方案：
1. 先解释修复思路
2. 列出需要修改的文件
3. 给出具体的代码变更

约束：
- 只修复这个问题，不做无关重构
- 保持向后兼容
```

## 常见 Bug 类型的处理

### 空指针/未定义错误

```
错误：Cannot read property 'x' of undefined

排查方向：
1. 检查变量初始化
2. 检查异步数据加载时序
3. 检查条件判断是否完整
```

### 类型错误

```
错误：Type 'X' is not assignable to type 'Y'

排查方向：
1. 检查类型定义是否正确
2. 检查数据转换是否完整
3. 检查泛型参数是否匹配
```

### 逻辑错误

```
现象：功能行为与预期不符

排查方向：
1. 添加日志追踪执行流程
2. 检查条件判断逻辑
3. 检查边界情况处理
```
