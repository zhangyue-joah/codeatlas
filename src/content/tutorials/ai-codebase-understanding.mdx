## 为什么用 AI 理解代码库

AI 工具在代码理解中的价值：

- **快速概览**：几分钟了解项目整体结构
- **解释代码**：用自然语言解释复杂逻辑
- **追踪调用**：快速找到函数的调用关系
- **回答问题**：针对代码库提问

## 提示词模板

### 获取项目概览

```
请帮我了解这个项目：
1. 这个项目是做什么的？
2. 使用了哪些主要技术栈？
3. 核心功能有哪些？
4. 项目的入口文件在哪里？
```

### 理解目录结构

```
请解释这个项目的目录结构：
1. 每个主要目录的职责是什么？
2. 核心代码在哪些目录？
3. 配置文件在哪里？
4. 测试代码在哪里？
```

### 追踪功能流程

```
我想理解 [功能名称] 的实现：
1. 用户操作从哪里开始？
2. 请追踪完整的调用链
3. 数据是如何流转的？
4. 涉及哪些关键文件？
```

### 理解具体代码

```
请解释这段代码：
@file [文件路径]

1. 这个函数/类的作用是什么？
2. 输入和输出是什么？
3. 关键逻辑是什么？
4. 有什么需要注意的地方？
```

## 探索策略

### 自顶向下

```
项目概览
├── 核心功能
│   ├── 功能 A 的实现
│   ├── 功能 B 的实现
│   └── ...
├── 技术架构
│   ├── 前端架构
│   ├── 后端架构
│   └── 数据层
└── 关键模块
    ├── 模块 A
    ├── 模块 B
    └── ...
```

### 问题驱动

1. 我要修改的功能在哪里？
2. 这个 Bug 可能在哪里？
3. 这个 API 是怎么实现的？
4. 数据是怎么存储的？

## 常见项目结构

### 前端项目（React/Vue）

```
src/
├── components/    # UI 组件
├── pages/         # 页面
├── hooks/         # 自定义 Hooks
├── services/      # API 调用
├── store/         # 状态管理
├── utils/         # 工具函数
└── types/         # 类型定义
```

### 后端项目（Node.js）

```
src/
├── controllers/   # 请求处理
├── services/      # 业务逻辑
├── models/        # 数据模型
├── routes/        # 路由定义
├── middlewares/   # 中间件
└── utils/         # 工具函数
```
