## 推荐的“开工模板”

无论你用的是哪一种 CLI Agent，建议把开工信息固定成这 5 行（可直接复制）：

1. 需求：\[一句话说明要做什么]
2. 验收标准（1-3 条）：\[可验证的结果]
3. 边界：只改 \[文件/目录]；不做无关重构；不新增依赖（如必须新增先申请）
4. 请先输出计划：文件清单 + 风险点 + 验证命令；我确认后你再生成补丁
5. 输出格式：优先 `git diff` 或逐文件变更摘要

## 为什么“先补丁后合并”更稳

把“生成改动”和“落地改动”分开：

- AI 负责产出可审计的 diff
- 你负责 review、应用、验证与提交

这比“一键写入+一键执行”更接近团队真实工作方式，也更可控。
