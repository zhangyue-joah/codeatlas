## 你要达到的“最小闭环”

不要一上来追求“能帮我写代码”。先跑通一次最小闭环：

1. AI **能通过 MCP 读取外部信息**（GitHub/本地文件）
2. AI **能基于证据给计划**（要改哪些、风险点、验证命令）
3. 你 **能审计与回滚**（知道它访问了什么、能撤销 token、能回退改动）

## 直接复制配置（推荐）

用这两个模板页起步：

- Starter Kit：`/templates/mcp-config-starter-kit`
- Claude Desktop 单独示例：`/templates/mcp-config-claude-desktop`

把里面的两处内容替换掉：

- `GITHUB_TOKEN`：换成你自己的 token（建议只读权限起步）
- `/ABSOLUTE/PATH/...`：换成你要授权的**单个项目目录**

## 最小验证提示词（可直接用）

把下面这段发给客户端（必要时改仓库信息）：

1. 读取这个目录的 `README`，总结项目是做什么的（不要改文件）
2. 列出你调用了哪些 MCP 工具（GitHub / filesystem），每次调用的目的是什么
3. 基于你读到的内容，给一个“只读”的改动计划：要改哪些文件、风险点、验证命令（先不要写入）

## 下一步：什么时候才开放写入/执行？

满足这些条件再考虑：

- 你能稳定拿到“计划 + 文件清单 + 验证命令”
- 你知道每个 server 的权限边界，并且能快速撤销
- 团队有审计与回滚约定（至少用 git）

否则就把 MCP 当成“更强的只读数据源”，已经能解决 80% 的提效场景。
