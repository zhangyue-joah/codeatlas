## 为什么用 AI 补测试

AI 工具在测试编写中的价值：

- **快速生成**：几秒钟生成基础测试框架
- **覆盖全面**：提醒你可能忽略的边界情况
- **减少重复**：自动生成相似的测试用例
- **学习参考**：展示测试的最佳实践

## 提示词模板

### 生成单元测试

```
请为以下函数生成单元测试：

[粘贴代码]

要求：
1. 使用 [Jest/Vitest/Pytest] 框架
2. 覆盖正常情况和边界情况
3. 包含错误处理测试
4. 测试描述要清晰说明测试场景
5. 遵循 AAA 模式（Arrange-Act-Assert）
```

### 生成集成测试

```
请为以下 API 端点生成集成测试：

[粘贴代码或 API 描述]

要求：
1. 测试成功响应
2. 测试错误响应（400、401、404、500）
3. 测试边界情况
4. Mock 外部依赖
```

### 补充边界情况

```
以下是现有的测试用例：

[粘贴现有测试]

请分析还有哪些边界情况没有覆盖，并生成补充测试。
```

## 测试类型指南

### 纯函数测试

```typescript
// 被测函数
function add(a: number, b: number): number {
  return a + b;
}

// AI 生成的测试
describe('add', () => {
  it('should add two positive numbers', () => {
    expect(add(1, 2)).toBe(3);
  });

  it('should handle negative numbers', () => {
    expect(add(-1, 1)).toBe(0);
  });

  it('should handle zero', () => {
    expect(add(0, 0)).toBe(0);
  });
});
```

### 异步函数测试

```typescript
// 被测函数
async function fetchUser(id: string): Promise<User> {
  const response = await api.get(`/users/${id}`);
  return response.data;
}

// AI 生成的测试
describe('fetchUser', () => {
  it('should return user data', async () => {
    const mockUser = { id: '1', name: 'Test' };
    vi.spyOn(api, 'get').mockResolvedValue({ data: mockUser });

    const result = await fetchUser('1');

    expect(result).toEqual(mockUser);
  });

  it('should throw on API error', async () => {
    vi.spyOn(api, 'get').mockRejectedValue(new Error('Not found'));

    await expect(fetchUser('invalid')).rejects.toThrow('Not found');
  });
});
```

## 测试质量检查清单

- [ ] 测试描述清晰说明测试场景
- [ ] 断言检查了正确的值
- [ ] 覆盖了正常路径
- [ ] 覆盖了边界情况
- [ ] 覆盖了错误处理
- [ ] Mock 只用于外部依赖
- [ ] 测试可以独立运行
- [ ] 故意破坏代码时测试会失败

## 常见边界情况

| 数据类型 | 边界情况 |
|----------|----------|
| 字符串 | 空字符串、超长字符串、特殊字符、Unicode |
| 数字 | 0、负数、小数、最大值、最小值、NaN |
| 数组 | 空数组、单元素、大数组、嵌套数组 |
| 对象 | 空对象、缺少字段、额外字段、null |
| 日期 | 无效日期、时区、闰年、边界日期 |
