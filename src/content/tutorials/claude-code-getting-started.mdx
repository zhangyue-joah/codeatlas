## 推荐的提示词骨架（复制就能用）

把下面这段当作“开工模板”：

1. 需求：\[一句话说明要做什么]
2. 验收标准（1-3 条）：\[可验证的结果]
3. 边界：只改 \[文件/目录]；不做无关重构；不新增依赖（如必须新增先申请）
4. 请先输出计划：改动文件清单 + 风险点 + 验证命令；我确认后你再生成 `git diff`

## 为什么建议“先只读”

终端 Agent 很容易给人一种“它能直接把项目修好”的错觉，但第一天最重要的是：

- 你能否稳定拿到**可审计的补丁**
- 你能否稳定留出**最小验证证据**

只要这两点跑通了，后面再逐步开放写入/执行权限才有意义。
